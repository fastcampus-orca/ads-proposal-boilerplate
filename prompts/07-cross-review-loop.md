orchestration으로 지금까지의 교차 검증을 이어서 완료해 줘.

- 요약과 수정 요청으로 현재 라운드를 확인하고 Codex 작성자와 Claude Code 평가자를 별도 대화로 배정해 줘. 작성자는 브리프·회사 문서·작성 양식만 받고, 수정 때 자기 초안과 반려 사유·수정 요청만 추가로 받게 해 줘.
- 평가자에게만 요구사항·고정 체크리스트·전체 평가를 전달해 줘. 코디네이터는 이 자료의 경로만 전달하고 평가 내용은 읽지 말고, 평가자가 보낸 판정 요약·수정 요청으로 진행해 줘.
- 평가자는 같은 8개 기준으로 독립 평가와 견적·성과 재계산을 함께 수행하고 실제 통과 수·N의 이유·원문 위치·이전 대비 변경을 남겨 줘. 평가 대상과 기준의 버전도 식별해 줘.
- 검산 전 잠정 평가가 있으면 그 검산부터, 수정 후 미평가 초안이 있으면 그 평가부터 이어 줘. N이 남으면 수정 요청만 작성자에게 전달하고 다음 라운드에서 전 항목을 재평가해 줘.
- 현재 평가가 검산까지 모두 Y면 바로 종료해 줘. 지금까지의 평가를 포함해 최대 3라운드이며, 세 번째에도 N이 남으면 미해결 이슈와 필요한 결정을 보고하고 멈춰 줘.
- 완료 보고만 믿지 말고 담당자가 실제 파일과 판정 근거를 확인하게 해 줘. 통과한 초안만 최종본으로 저장하고 요약에 실제 라운드·종료 이유를 남겨 줘. 오류·점수·반려 횟수를 의도적으로 만들지 마.
