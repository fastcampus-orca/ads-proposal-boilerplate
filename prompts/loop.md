제안서·견적서의 작성·평가·반려 후 수정을 진행하고, 통과한 최종 제안서와 교차 검토 보고서를 만들어 줘.

## 역할

- 새 Codex 작성자 워커와 새 Claude Code 평가자 워커를 시작하고, 너는 코디네이터로 작업 전달·진행 확인·종료를 관리해 줘.
- 작성자는 브리프·회사 문서·요구사항·제안 및 견적 양식·샘플로 초안을 작성하고, 반려되면 자기 초안과 수정 요청을 바탕으로 수정하게 해 줘. 체크리스트·전체 평가는 전달하지 마.
- 평가자는 초안을 직접 고치지 않고 검사·검산·판정과 평가 기록·수정 요청 작성까지만 맡게 해 줘. 통과 후에는 전체 검토 과정을 보고서로 정리하게 해 줘.

## 진행

1. 프로젝트 지침·저장 규칙과 확정된 요구사항·체크리스트를 읽어 줘. 검산 스크립트는 아래 폴더에서 찾고, 지침에 기록된 실행 방법을 확인해 재사용해 줘. 필요한 기준이나 스크립트가 없으면 임의로 만들지 말고 누락된 자료를 알려 줘.
2. 기존 라운드는 보존하고 다음 번호부터 시작해 줘. 작성자가 이전 초안·평가·최종본을 읽거나 복사하지 않고 내부 검토용 초안을 새로 작성하게 해 줘. 양식의 필수 구성을 따르고 샘플은 구성·표현만 참고하게 해 줘.
3. 평가자가 체크리스트 전 항목을 검사하고, 계산이 필요한 항목은 현재 초안의 입력값으로 검산 스크립트를 실행하게 해 줘. 내용 검토도 함께 수행하고 실제 판정·통과 수·근거를 같은 라운드의 평가 기록에 남기게 해 줘.
4. 반려되면 모든 N 항목과 수정 요청을 해당 라운드의 revision-request.md에 저장하게 해 줘. 이를 작성자에게 전달해 다음 라운드에 수정본을 저장하게 하고, 평가자가 같은 기준의 전 항목을 재검사하게 해 줘. 수정 전후 내역은 해당 라운드 평가에 남겨 줘.

## 종료와 산출물

- 이번 초안의 첫 평가부터 최대 3라운드까지만 진행해 줘. 기준을 낮추거나 추가 라운드를 만들지 마.
- 한도까지 반려가 남으면 미해결 항목을 보고하고 종료해 줘. 이 경우 최종본은 만들거나 갱신하지 마.
- 통과하면 반복을 끝내고, 작성자가 통과한 초안을 최종 제안서 Markdown으로 저장하고, 평가자는 이번 전체 라운드로 교차 검토 보고서 양식을 채우게 해 줘. 보고서에는 시작·종료 라운드, 반려와 수정 과정, 첫 초안과 최종본 비교, 최종 판정을 담아 줘. 샘플은 구성·표현만 참고하게 해 줘.
- 내가 정리를 승인할 때까지 기존 워커·새 워커와 터미널을 유지해 줘.

## 최종 HTML 작성·확인

- 통과한 두 Markdown을 대응하는 디자인 참고본에 맞춰 HTML로 만들어 줘. 색상·글꼴·배치·표·다크/라이트 전환을 적용하고, 구성과 분량은 실제 내용에 맞춰 줘. 저장 위치·파일명은 README를 따라 줘.
- 최종 HTML은 제안서와 교차 검토 보고서 2개만 만들어 줘. 초안·평가 기록 등 근거 문서는 참고용으로만 사용하고 별도 HTML로 만들거나 링크하지 마. 필요한 근거는 문서명·라운드·항목을 일반 텍스트로 남겨 줘.
- 코디네이터인 네가 두 HTML의 모든 내부 링크를 확인해 줘. 브라우저에서 문서 간 이동과 목차·버튼의 페이지 내 이동을 직접 실행해 대상 파일·구역이 맞게 열리는지 확인해 줘. 깨진 링크·잘못된 이동은 수정하고, 워커가 붙인 근거 문서 링크나 불필요한 이동 버튼은 제거해 줘.
- 수정한 파일을 다시 열어 링크 동작·화면 표시·테마 전환과 Markdown 내용 일치를 확인한 뒤 완료를 보고해 줘. 확인하지 못한 항목은 구분하고, 미리보기 주소·라운드별 판정·결과 파일 경로를 알려 줘.
