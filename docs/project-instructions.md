# 프로젝트 작업 지침

> 바른그로스의 광고 운영 제안·견적 업무에 적용하는 가상 제공본입니다.

## 적용 범위

- 회사·활동: 1인 광고 운영 대행사 바른그로스
- 적용할 업무: 고객사의 브리프를 받아 제안·견적서를 작성하고 독립 평가로 개선

## 작업 시작

- `docs/about-company.md`와 `docs/company-rules.md`를 읽고 대행사와 고객사를 구분한다.
- 본인 회사 문서가 있으면 제공본 대신 그 문서를 사용하고 실제 적용 경로를 확인한다.
- 브리프에서 목표·예산·기간·수수료율·제출 내용을 확인한다.

## 작업 진행

- Codex 작성자는 브리프와 회사 문서로 초안을 작성한다. 평가자의 요구사항 정리·체크리스트·전체 평가 기록·평가 샘플을 읽지 않는다.
- Claude Code 평가자는 요구사항과 체크리스트를 준비하고 초안을 검증한다. 제안서 본문은 직접 고치지 않는다.
- 수정 시 작성자는 자기 직전 초안과 평가자가 전달한 반려 이유·수정 요청만 추가로 사용한다.
- 문서 저장과 라운드 관리에는 `README.md`를 적용한다.

## 결과 검토

- 작성자는 사규에 따라 수치·근거·표현을 자체 검토하고 제출한다.
- 평가자는 사규를 브리프 조건과 연결해 8개 기준으로 판정하고 실제 Y 개수와 이전 라운드 대비 변화를 기록한다.
- 전 항목 Y일 때만 통과시키며 원하는 개선 곡선을 만들기 위해 오류를 넣거나 판정을 조정하지 않는다.

## 판단이 필요한 상황

- 필수 입력이 없거나 조건이 충돌하면 영향과 필요한 결정을 사용자에게 알린다.
- 기준 변경이 승인되면 변경 이유를 남기고 새 기준으로 다시 평가하며, 이전 점수와 단순 비교하지 않는다.
