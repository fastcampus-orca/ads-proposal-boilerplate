# 광고 운영 대행 제안·견적서

Codex가 광고 운영 대행 제안·견적서를 작성하고 Claude Code가 독립 평가하는 교차 검증(Generator–Evaluator) 프로젝트입니다. 브리프와 회사 문서로 시작해 반려 사유를 반영하고, Orca 오케스트레이션으로 통과할 때까지 작성·평가를 반복합니다.

## 시작하기

1. 저장소를 Fork → Clone하고 Orca에서 열기.
2. Part 4 Chapter 4의 company-identity 인터뷰로 만든 본인 회사 문서가 있으면 사용하고, 없으면 `docs/`의 제공본 사용.
3. 작성용 Codex와 평가용 Claude Code를 별도 대화로 열고 역할별 입력 확인.
4. 아래 스킬 설치 상태 확인 후 제공 브리프로 개별 실습 시작.

`AGENTS.md`가 공통 지침 원본이고 `CLAUDE.md`는 이를 가리키는 상대 심볼릭 링크입니다. 회사 문서 3종, 양식 4종, 다른 소재의 샘플 4종, 실습용 브리프를 제공합니다. 본인 회사 문서는 `docs/`의 대응 파일로 옮기거나 실제 경로를 `docs/project-instructions.md`에 기록합니다. 빈 폴더의 `.gitkeep`은 Git에 폴더를 남기는 파일입니다.

## 전체 구조 이해

```text
브리프 + 회사 문서
├─ Codex: 제안·견적서 작성
└─ Claude Code: 요구사항 → 비공개 체크리스트 → 초안 평가
   ├─ 반려 → 수정 요청만 Codex에 전달 → 수정·재평가
   └─ 8/8 통과 → 최종본 저장
```

```text
ads-proposal-boilerplate/
├── README.md
├── AGENTS.md
├── CLAUDE.md -> AGENTS.md
├── docs/                # 대행사의 회사 소개서·사규·작업 지침
├── templates/           # 항목만 있는 빈 양식 4종
├── samples/             # 가상 소재로 채운 샘플 4종
└── artifacts/
    ├── sources/         # 제공 brief.md 및 받은 자료
    ├── rules/           # 실습 중 만들 요구사항·평가 체크리스트
    ├── drafts/          # 라운드별 제안·견적서
    ├── review/          # 라운드별 평가 기록
    └── final/           # 통과본
```

## 공통 작업 규칙

### 역할별 입력

작성자에게는 브리프와 회사 문서만 내용 입력으로 제공합니다. 체크리스트는 평가자만 가지며 작성자에게 공개하지 않습니다. 작성 양식과 공통 저장 규칙은 사용할 수 있습니다.

| 역할 | 읽을 자료 | 전달할 결과 |
| --- | --- | --- |
| Codex 작성자 | 브리프·회사 문서, 수정 시 자기 직전 초안과 반려 이유·수정 요청 | 라운드별 초안 |
| Claude Code 평가자 | 브리프·회사 문서·요구사항·체크리스트·초안·이전 평가 | 전체 평가 기록, 작성자에게는 반려 이유·수정 요청만 전달 |
| 코디네이터 | 파일 경로·라운드·평가 완료 여부와 통과 개수 | 다음 작업 배정 또는 최종본 저장 |

작성자는 `artifacts/rules/`·`artifacts/review/`와 평가 양식·샘플을 읽거나 전체 폴더 검색으로 수집하지 않습니다. 체크리스트를 준비하거나 본 대화를 작성에 재사용하지 않습니다. 코디네이터도 체크리스트 본문과 전체 평가를 작성자에게 전달하지 않습니다. 이는 같은 저장소에서 지침으로 입력을 분리하는 방식이며 파일 접근 권한을 차단하는 장치는 아닙니다.

### 문서 저장

모든 경로는 프로젝트 루트 기준입니다. N은 1부터 시작하는 라운드 번호이며, 양식의 빈 칸을 실제 작업 문서에 채웁니다.

| 문서 | 사용할 양식 | 저장 위치 |
| --- | --- | --- |
| 대행사 회사 문서 | 제공본 또는 Part 4 본인 문서 | `docs/about-company.md`·`docs/company-rules.md`·`docs/project-instructions.md` |
| 클라이언트 브리프 | 제공 자료 | `artifacts/sources/brief.md` |
| 요구사항 | `templates/requirements-template.md` | `artifacts/rules/requirements.md` |
| 평가 체크리스트 | `templates/evaluation-checklist-template.md` | `artifacts/rules/evaluation-checklist.md` |
| 제안·견적서 | `templates/proposal-quote-template.md` | `artifacts/drafts/round-N.md` |
| 평가 기록 | `templates/evaluation-template.md` | `artifacts/review/round-N.md` |
| 통과본 | 통과한 라운드의 제안·견적서 | `artifacts/final/proposal-quote.md` |

- `templates/`는 빈 양식으로 유지합니다. `samples/`의 소재·수치·출처는 가상 값이므로 실제 제안의 근거로 쓰지 않습니다.
- 평가자는 요구사항에 브리프의 해당 절과 연결 사규를 적습니다. 제공 정보·작성자의 가정·추가 확인 사항을 구분하고, 외부 근거를 썼다면 출처와 확인일을 남깁니다.
- 수강생이 확정한 체크리스트를 모든 라운드에 동일하게 적용합니다. 각 항목은 Y/N 판정이 가능한 한 문장과 확인 근거 한 줄로 쓰며, 통과를 위해 기준을 완화하지 않습니다.
- Codex는 초안·수정을, Claude Code는 평가를 맡습니다. 평가자는 초안을 직접 고치지 않고 수정 요청을 남깁니다.
- 평가를 받은 초안은 보존하고 수정본은 다음 번호로 저장합니다. 평가 대상과 기록의 라운드 번호를 맞춥니다.

### 평가 기록

Claude Code는 실제 브리프·회사 문서·요구사항·체크리스트·초안을 읽고 전 항목의 Y/N과 근거 위치를 기록합니다. 누락되거나 확인할 근거가 부족하면 N이며, N에는 반려 이유와 통과에 필요한 수정 내용을 적습니다. 계산은 합계만 보지 않고 광고비·수수료·부가세·계약 총액과 가격 산정 근거까지 확인합니다.

매 평가에 실제 통과 개수와 누적 라운드별 변화를 기록합니다. 8/8일 때만 통과, 하나라도 N이면 반려입니다. 3/8 → 6/8 → 8/8은 개선 표시 방식의 예시이며 정해진 결과가 아닙니다. 오류를 일부러 넣거나 점수를 맞추지 않으며 첫 라운드에 통과할 수도 있습니다. 미평가 항목이 있으면 평가 미완료로 두며 최종본을 만들지 않습니다. 기대 성과의 목표 미달은 숨기지 않고 차이와 대응을 확인하며, 추정치가 목표와 같다는 이유만으로 통과시키지 않습니다.

Ch03-03의 추가 검산은 같은 라운드 기록에 근거를 추가하고, 판정이 바뀌면 이전 판정·정정 이유도 남깁니다. 초안 내용이 바뀌면 다음 라운드에서 전 항목을 다시 평가합니다.

### 전체 루프

개별 실습의 입력과 확정 기준을 재사용하고 기존 라운드 번호 다음부터 이어 갑니다. 코디네이터는 공통 지침·담당 양식과 역할별로 허용된 입력만 전달합니다. 평가자가 반려 이유·수정 요청만 추려 작성자에게 넘기고 전체 평가 기록은 평가자 쪽에 보존합니다. 새 워커는 이전 대화를 모른다고 가정합니다.

반려되면 Codex 수정 → Claude Code 전 항목 재평가를 반복합니다. 코디네이터는 완료 보고뿐 아니라 평가자가 기록한 8/8·통과 판정과 대상 초안 경로를 확인한 후 해당 초안을 최종 경로에 복사합니다. 기준 충돌·자료 부족·도구 오류로 진행할 수 없으면 중단 이유와 필요한 입력을 기록하고 수강생에게 알립니다. 중단을 통과로 처리하지 않습니다.

### 스킬 설치

orchestration·orca-cli는 Part 4의 기존 설치를 사용합니다. Ch04-02 전에 두 에이전트에서 스킬을 읽을 수 있는지 확인합니다. 미설치 상태라면 Part 4 설치 안내에 따라 설치하며, 스킬 폴더나 설치 완료 상태는 기본 뼈대에 미리 넣지 않습니다.

프로젝트에 스킬을 설치할 경우 원본·참조 파일은 `.agents/skills/<스킬명>/`에 두고 `.claude/skills/<스킬명>`은 해당 원본으로 연결하는 상대 심볼릭 링크로 만듭니다. 기존 설치·수정은 보존합니다.
