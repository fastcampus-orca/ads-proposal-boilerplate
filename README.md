# 광고 제안서·견적서 교차 검증

Orca에서 Codex가 제안서를 쓰고 Claude Code가 독립 평가하여, 반려 사유를 반영하는 교차 검증 프로젝트입니다. 가상 대행사 바른그로스가 고객사 무브펫의 광고를 제안합니다.

## 시작하기

1. 이 시작 뼈대를 내 작업 폴더로 복제하고 Orca에서 엽니다.
2. 에이전트에게 프로젝트 지침과 폴더 구조를 읽고 준비 상태를 파악하도록 요청합니다.
3. 아래 개별 프롬프트를 순서대로 실행한 뒤 자동 루프로 이어갑니다. 참고자료 입력 칸에는 역할에 맞는 실제 파일을 연결합니다.

회사 문서 3종, 양식 4종, 다른 소재의 샘플 4종, 무브펫 브리프와 실행 요청문을 제공합니다. 결과 폴더의 `.gitkeep`은 빈 폴더를 Git에 남기기 위한 파일입니다. `AGENTS.md`가 지침 원본이며 `CLAUDE.md`는 원본의 상대 경로 심볼릭 링크입니다. Part 4에서 확인한 `orchestration`·`orca-cli`를 사용합니다.

## 역할과 저장 규칙

| 역할 | 읽을 자료 | 맡을 일 |
| --- | --- | --- |
| Codex 작성자 | 브리프, 회사 문서 3종, 제안·견적 양식 | 초안 작성, 자기 초안과 전달된 반려 사유·수정 요청으로 수정 |
| Claude Code 평가자 | 브리프, 회사 문서, 요구사항·체크리스트·평가 양식, 평가 대상 초안 | 요구사항·고정 기준 작성, 전 항목 평가와 검산, 수정 요청 작성 |
| 코디네이터 | 공통 지침, 실행 단계, 평가자의 판정 요약·수정 요청 | 역할별 자료 전달, 실제 산출물 확인, 재배정·종료 관리 |

체크리스트와 전체 평가는 평가자만 보유합니다. 코디네이터는 작성자에게 반려 사유·수정 요청만 전달합니다. 이는 작업 맥락 분리이며 파일 접근을 막는 보안 기능은 아닙니다. 양식은 빈 항목을, 샘플은 다른 고객인 가상 문구 브랜드 노트온의 형식을 보여 줍니다. 샘플의 내용·수치·판정을 실제 작업 근거로 쓰지 않습니다.

모든 출력 경로는 아래 표에 한 번만 정의합니다. `{N}`은 1부터 3까지의 라운드입니다. 이전 라운드의 초안과 평가는 보존합니다.

| 문서 | 저장 위치 |
| --- | --- |
| 요구사항 정리 | `artifacts/rules/requirements.md` |
| 고정 체크리스트 | `artifacts/rules/evaluation-checklist.md` |
| 라운드별 제안·견적 초안 | `artifacts/drafts/round-{N}.md` |
| 라운드별 전체 평가와 검산 | `artifacts/review/round-{N}.md` |
| 작성자에게 전달할 반려 사유·수정 요청 | `artifacts/review/revision-request-{N}.md` |
| 라운드 요약·종료 사유·미해결 이슈 | `artifacts/review/summary.md` |
| 통과한 제안·견적 최종본 | `artifacts/final/proposal-quote.md` |

첫 평가 전에 기준을 한 번 고정하고 같은 8개 ID로 평가합니다. 평가자는 Y 개수, N의 이유, 브리프·사규·초안의 원문 위치, 독립 재계산, 이전 초안 대비 변경을 남깁니다. 세부 검산이 완료된 8/8 Y만 통과이며 하나라도 N이면 반려합니다. 처음부터 통과하면 그대로 종료하고, 최대 3라운드에서 미통과면 최종본을 만들지 않고 이슈를 보고합니다.

개별 실행에서는 독립 평가 후 견적 검산을 추가하여 같은 라운드의 판정을 확정합니다. 처음 판단과 보완한 판단을 모두 기록하며, 검산 전에는 통과본을 만들지 않습니다. 수정 후에는 동일한 기준으로 평가와 검산을 모두 다시 합니다. 통합 실행은 이 두 검토를 매 라운드 함께 진행합니다.

첫 평가에서 통과하면 실제 결과를 보존하고, 필요할 때 실제 기록과 구분한 연습용 재현 예시로 수정 과정을 보완합니다.
